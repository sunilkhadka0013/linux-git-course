Version control

What is version control?

A system that records changes to files over time.

  • Remembers every change, who made it and when
  • Restores any earlier version when you need it
  • Compares two versions to see exactly what changed

  • Which file is the latest?
  • What changed between them?
  • Who changed it, and why?

Version control

Why do developers need it?

History

Go back to any point when something breaks.

Teamwork

Many people work on the same code at once.

Safe experiments

Try ideas without risking the working version.

Accountability

Every change has an author and a reason.

Problems Git solves

Problem How Git helps
Lost or overwritten work Every saved snapshot stays in history
"It worked yesterday" Compare versions and roll back
Two people edit the same file Changes are merged, conflicts are flagged
Risky new features Branches keep experiments separate
Working offline Full history lives on your computer

Git

What is Git?

  • A free, open-source version control system
  • Created by Linus Torvalds in 2005 for the Linux kernel
  • Runs locally, with no server required
  • Fast, and built to handle huge projects

Git

Git vs GitHub

Git

  • A tool on your computer
  • Tracks changes to your files
  • Works without internet

GitHub

  • A website that hosts Git repositories
  • Adds sharing, reviews and issues
  • Alternatives: GitLab, Bitbucket

Git is the tool. GitHub is a place to put what the tool tracks.

Types of version control

Centralized

Developers

Hold only the files they are working on

⇄every action

Central server

The single home of the full history

  • Examples: SVN, CVS, Perforce
  • If the server is down, nobody can save history

Types of version control

Distributed

Every developer

Has a full copy of the project and its history

⇄push / pull

Shared remote

A common place to exchange changes, such as GitHub

  • Examples: Git, Mercurial
  • Work and commit offline; a lost copy can be restored from any other
