Setup

Installing Git

  • Windows git-scm.com/downloads/win
  • macOS brew install git
  • Ubuntu / Debian sudo apt install git
  • Fedora sudo dnf install git

Check that it worked:

$ git --version
git version 2.47.1   # your number may differ

Setup

Tell Git who you are

git config changes Git's settings.

$ git config --global user.name "John Doe"
$ git config --global user.email "johndoe@example.com"
$ git config --global init.defaultBranch main  # first branch name
  • Your name and email are saved inside every commit, so everyone can see who made each change
  • With --global, you set them once for all your repositories
  • Use your GitHub email, so commits link to you

Setup

With and without setup

Without setup

$ git commit -m "Add README"
Author identity unknown
*** Please tell me who you are.

The commit fails. On some computers, Git instead guesses, and saves something like johndoe@Johns-Laptop.local.

With setup

$ git commit -m "Add README"
$ git log -1
Author: John Doe <johndoe@example.com>

The commit is saved with your name and email (log output shortened).

Setup

Checking your configuration

$ git config --list        # every setting
$ git config user.name     # one setting
Level Applies to
--system Every user on the computer
--global All your repositories
--local Only the current repository

The closer level wins: local overrides global, global overrides system.

Repositories

What is a Git repository?

A project folder whose history Git is tracking.

my-project/
├── .git/        ← history and settings
├── README.md    ← your files
└── notes.txt
  • Git stores everything it knows in .git/
  • The folder is hidden: see it with ls -a
  • Delete .git/ and the local history is gone

Repositories

git init

Turns a folder into a repository.

$ mkdir my-project
$ cd my-project
$ git init
Initialized empty Git repository in /home/johndoe/my-project/.git/
  • Run it once per project
  • It works in an existing folder too, and does not change your files
  • Do not run it in your home folder

Saving changes

git status

$ echo "# My project" > README.md
$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	README.md

nothing added to commit but untracked files present (use "git add" to track)

Shows what has changed and what is staged. It changes none of your files, so run it often.

Saving changes

States of a file

State Meaning
Untracked New file that Git is not following yet
Modified Tracked file with changes that are not staged
Staged Change marked to go into the next commit
Unmodified Tracked file with nothing new since the last commit

Short view: git status -s shows ?? for untracked and M for modified.

Saving changes

git add

Stages changes for the next commit.

$ git add README.md           # one file
$ git add index.html app.js   # several files
$ git add .                   # everything in this folder and below
  • You choose what goes into each commit
  • If you edit a file after adding it, add it again
  • Check git status before using git add ., so no passwords or junk files slip in

Saving changes

git commit

Saves the staged changes as a snapshot in history.

$ git commit -m "Add README"
[main (root-commit) 0ad094b] Add README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
  • Each commit has an ID, author, date and message
  • Only staged changes are included
  • Without -m, Git opens a text editor for the message

Commit messages

Why messages matter

A message tells your team, and future you, what changed and why.

Unclear Clear
update Add installation steps to README
fix Fix crash when email field is empty
changes Remove unused logo images
asdfgh Rename config file to settings.json

Fixing commits

Rewrite or undo a commit

For your latest commit.

# rewrite the message
$ git commit --amend -m "Add notes file"

# undo the commit, keep the changes staged
$ git reset --soft HEAD~1
  • --amend also adds anything staged to that commit
  • HEAD~1 means one commit back, so there must be an earlier commit
  • Both change history, so use them only on commits you have not pushed

Commit messages

Writing a good message

  • Keep the first line short, about 50 characters
  • Start with a verb: Add, Fix, Remove
  • Add a blank line, then explain why if needed
  • One commit, one logical change
Fix login button on mobile

The button was hidden behind
the footer on small screens.

Tip: complete the sentence "If applied, this commit will …"

Commit messages

Commit message styles

Type Use it for Example
feat: A new feature feat: add login page
fix: A bug fix fix: stop crash on empty email
docs: Documentation only docs: add setup steps to README
refactor: Restructure code, same behaviour refactor: split user form into parts
chore: Other upkeep chore: remove unused files
style: Formatting, no logic change style: fix indentation in app.js
perf: Make it faster perf: cache product list
test: Add or update tests test: add tests for login form
build: Build system or dependencies build: upgrade React to version 19
ci: Automation pipeline settings ci: run tests on every push

Focus on the five highlighted types. The others are optional. Format: type: short description, known as Conventional Commits.

Managing files

git rm

Removes a file and stages the removal.

$ git rm notes.txt
rm 'notes.txt'
$ git commit -m "Remove notes"
Command File on your disk Tracked by Git
git rm file Deleted No, after commit
git rm --cached file Kept No, after commit

Earlier commits still contain the file. Removing it does not erase a leaked password.

Managing files

git mv

Renames or moves a file and stages the change.

$ git mv notes.txt todo.txt
$ git status
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	renamed:    notes.txt -> todo.txt
$ git commit -m "Rename notes to todo"

It does the same job as mv, then git rm on the old name and git add on the new one.

Sharing changes

git push

Uploads your commits to GitHub.

# once: connect to an empty repository you created on GitHub
$ git remote add origin https://github.com/<username>/my-project.git
# send your commits
$ git push origin main
  • origin is the usual name for your remote repository
  • Only committed changes are pushed
  • Signing in to GitHub is covered in Module 04

Recap

Key takeaways

  • git config sets who you are; git init creates a repository
  • Edit, then git add, then git commit
  • git status shows where you are
  • git rm and git mv remove and rename tracked files

Once per project
