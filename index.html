Part 1

Linux

The operating system behind most of the internet.

Linux

What is Linux?

  • An open-source operating system kernel, created by Linus Torvalds in 1991
  • A distribution (distro) bundles the kernel with tools, a desktop and a package manager
  • Free to use, inspect, modify and share
  • Built around the command line: small tools that do one thing well

Linux

Why it matters

Servers

The majority of web servers run Linux.

Cloud

AWS, Azure and GCP machines are mostly Linux.

Containers

Docker and Kubernetes are built on Linux features.

Everywhere

Android, routers, smart TVs, supercomputers.

Linux

Choosing a distro

Ubuntu

Friendly and well documented. Best starting point.

Debian

Stable and conservative. Common on servers.

Fedora

Modern packages, backed by Red Hat.

Arch

Minimal and hands-on. Learn by building.

Tip: you can try Linux on Windows with WSL, or on any OS with a virtual machine.

Linux

Everything is a file

# one tree, starting at /
/
├── home/    # your files
├── etc/     # configuration
├── var/     # logs, changing data
├── usr/     # installed programs
├── bin/     # essential commands
├── tmp/     # temporary files
└── dev/     # devices as files
  • No drive letters, just one tree
  • ~ is your home folder
  • Paths are case-sensitive

Linux

Commands to learn first

$ pwd                  # where am I?
$ ls -la               # list files, including hidden
$ cd projects          # move into a folder
$ mkdir notes          # create a folder
$ touch todo.txt       # create an empty file
$ cp a.txt b.txt       # copy
$ mv b.txt docs/       # move or rename
$ rm todo.txt         # delete (no recycle bin!)
$ man ls              # read the manual

Linux

Power moves

Pipes & search

$ cat app.log | grep ERROR
$ ls | wc -l
$ history | tail
$ find . -name "*.js"

Permissions

$ ls -l script.sh
-rwxr-xr-- 1 you staff script.sh
$ chmod +x script.sh
$ sudo apt update

r = read, w = write, x = execute, for owner, group, others.

Part 2

Git

A time machine and a collaboration tool for your code.

Git

Why use version control?

  • Save snapshots (commits) of your project at any point
  • Go back to any earlier version when something breaks
  • Try ideas safely on branches
  • Work with others without overwriting each other
  • No more final_v2_REAL_final.zip

Git

Git is not GitHub

Git

The tool. Runs on your machine, tracks changes locally. Works offline.

GitHub

A website that hosts Git repositories, adds pull requests, issues and Pages. GitLab and Bitbucket are alternatives.

Git

The basic flow

Working folder

Where you edit files

→git add

Staging area

What goes in the next commit

→git commit

Local repo

Your saved history

→git push

Remote

GitHub

Git

Your first repository

$ git init                         # start tracking this folder
$ git status                       # what changed?
$ git add index.html               # stage a file
$ git commit -m "Add home page"    # save a snapshot
$ git log --oneline                # view history
$ git remote add origin <url>      # connect to GitHub
$ git push -u origin main          # upload

Git

Branches

$ git switch -c feature/login
# ...edit, add, commit...
$ git switch main
$ git merge feature/login
$ git branch -d feature/login
  • A branch is a cheap, movable pointer
  • Keep main working
  • Open a pull request to review before merging

Git

Habits that help

Small commits

One idea per commit. Easier to review and to undo.

Clear messages

"Fix login redirect" beats "stuff".

Use .gitignore

Never commit secrets, passwords or node_modules.
